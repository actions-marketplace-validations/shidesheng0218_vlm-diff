# 0 token 精准描述 99.3% 的 UI 变化：把 DOM 当 Ground Truth 用到底

> **数据快照：145 对 / 611 区域版本** — 文中 "99.3%" 为该快照测量。最新全量（193 对 / 662 区域，results/router-replay.json）：97.1% 区域（643/662）零 token 确定性作答，区域升级率 2.9% — 以 README 为准。

> 开源项目 vlm-diff：https://github.com/shidesheng0218/vlm-diff  
> 英文版：https://dev.to/shidesheng/building-a-visual-regression-tool-with-vlms-and-dom-diffing-1j4m

## 前言

最近在做 UI 自动化回归测试，遇到一个棘手问题：**传统像素 diff 误报太多**（字体渲染抖动、抗锯齿差异），而 **GPT-4V/Claude 这些视觉大模型漏报也很严重**（对细微变化不敏感）。

翻了一圈 Paper，发现今年 3 月发的 [VLM-SubtleBench](https://arxiv.org/abs/2603.07888) 直接把顶级 VLM 打脸了：

- **GPT-5-thinking**：77.8% 准确率（人类基线 95.5%）
- **Claude Sonnet 4**：62.6%
- **GPT-4o**：61.6%

在空间位移检测上更惨：**人类 95%，最强模型只有 59.9%**。而且把前后图拼成一张大图喂给模型，10 类变化里 9 类反而更差。

但 UI 测试场景有个天然优势：**我们有 DOM 结构作为 Ground Truth**。

于是写了这个实验项目 **vlm-diff**，先验证了一个假设：

> **DOM diff + 像素 diff → VLM 分类** 的混合架构，比纯 VLM 方案召回率高 33 个百分点、误报率 0%。

然后在这个基础上又往前走了一步，得到了一个更有意思的结果：

> **DOM diff 不只能告诉你"哪里变了"，还能直接告诉你"变成了什么"——99.3% 的变化区域根本不需要调用 VLM。**

## 核心思路

![架构图](https://raw.githubusercontent.com/shidesheng0218/vlm-diff/master/docs/pipeline-demo.gif)

### Stage 1：确定性检测（0 token）

**DOM Diff**：
- 元素增删（结构路径逐节点对比）
- 位置/尺寸变化（`getBoundingClientRect`，带 1px 抖动容差）
- 文本/样式改动（`textContent`、7 个 `computedStyle` 字段）
- **记录每个字段的 before/after 值**（后面会用到，这是关键）

**像素 Diff**：`pixelmatch` + 连通域聚合，作为 DOM 之外的兜底信号。

**无变化抑制**：
```typescript
if (domChanges.length === 0) {
  return { changed: false, regions: [] };  // DOM 没变 → 直接判定无变化
}
```
这一条规则在 145 对样本上（含 6 对无变化对照）做到了 **139/139 变化全检出、0/6 误报**，且两次运行逐字节一致——纯 VLM 检测做不到这一点（同样模型同样输入，两轮跑出了不同的漏报和一次误报）。

### Stage 2：分层描述——重点来了

之前的架构是：检测到区域 → 裁剪 → 扔给 VLM 分类。但我们后来意识到一个问题：

**DOM diff 早就知道答案的大部分了。**

`backgroundColor: rgb(37,99,235) → rgb(220,38,38)`，规则模板直接就能生成：

> "Element background color changed from blue (rgb(37, 99, 235)) to red (rgb(220, 38, 38))"

为什么要花钱请 VLM 重新从裁剪图里"看出来"？所以现在的架构是每个区域先过一遍路由：

- **Tier A（确定性，0 token）**：颜色、文本、样式属性、元素增删、几何变化——全部模板生成，confidence = 1.0
- **Tier B（VLM）**：只有"像素变了但 DOM 没变"的区域（Canvas 重绘、动画中间帧）才升级给 VLM

几个值得一提的实现细节：

**1. 颜色命名**：计算样式是 `rgb()` 格式，写了个 40 行的锚点色板就近匹配（感知加权 RGB 距离），零依赖。

**2. 根因归因（这个最有意思）**：真实布局变化是级联的——删一张卡片，后面所有兄弟节点的 rect 都会位移。怎么区分"谁主动变了、谁是被动挪了"？看 changedFields：一个区域**只有**几何字段（position/size）变化，而同组里存在带非几何变化（文本/颜色/增删）的区域，它就是"级联追随者"，描述会写成：

> "moved 24px up **as part of a layout shift caused by a nearby change**"

**3. pair 级别类型判定用根因优先**：删卡片时容器收缩区域通常比被删卡片本身还大，按"取最大区域"的惯例会把整对样本误判成 size-change。改成根因区域优先后，离线类型准确率从 82.7% 提到 90.6%。

## 实验数据

### 检测层（145 对，0 API 调用）

139/139 变化对全检出，0/6 无变化误报。

### 真实 API 三臂对照（Kimi K3，15 对代表性子集，跑了两轮）

| 指标 | 纯 VLM 全图 | 管线（无 hint） | 管线 + DOM hint |
|------|------------|----------------|-----------------|
| 召回率（12 变化对） | 66.7% | **100%** | **100%** |
| 无变化误报（3 对） | 33.3% | **0%** | **0%** |
| 端到端类型准确率 | 66.7–75% | 66.7% | **83.3%** |
| 平均输入 tokens/对 | ~1505 | ~583 | ~692 |

**一个反直觉的发现**：单纯"裁剪后分类"是**不行**的——同样的裁剪图，不给 DOM 字段提示时条件分类准确率只有 58–67%（对比全图方案的 100%）。原因是裁剪把类型判断需要的参照系裁掉了：判断圆角变化需要看到其他几个角，判断颜色偏移需要别的色块参照。但把检测器已知的 `changedFields` 作为 ~50 token 的文本提示传给模型，差距就被补回来了（83.3%）。

### 分层路由离线回放（145 对全量，0 API 调用）

| 变化类型 | 区域数 | 确定性描述 | 需 VLM |
|----------|--------|-----------|--------|
| size-change | 136 | 136 | 0 |
| spatial-shift | 122 | 122 | 0 |
| element-remove | 122 | 122 | 0 |
| color-change | 94 | 94 | 0 |
| text-change | 62 | 62 | 0 |
| element-add | 41 | 41 | 0 |
| style-change | 34 | 30 | 4（像素级阴影重绘） |
| **合计** | **611** | **607（99.3%）** | **4（0.7%）** |

**端到端类型准确率 90.6%（126/139），VLM token 消耗为 0**。对比：带 hint 的完整 VLM 管线是 83.3%（且每对 ~692 输入 token）。

也就是说：在 DOM 可观测的回归场景下，**确定性方法的准确率反超了 VLM**，因为 DOM diff 拿到的是精确值，VLM 是在"猜"。

### 真实 API 四臂验证（Kimi K3，36 对，总花费 $0.18）

光离线回放还不够，把 tiered 臂加进真实 API 对照跑了一轮：

| 指标 | **tiered** | 管线+hint | 管线无 hint | 纯 VLM 全图 |
|------|-----------|----------|------------|------------|
| 召回率（30 变化对） | **100%** | 100% | 100% | 76.7% |
| 端到端类型准确率 | **100%**（30/30） | 93.3% | 56.7% | 95.7%（但漏了 7 对） |
| avg tokens/对 | **11+4** | 910+388 | 782+611 | 1505+196 |

三个细节：

1. **75 个区域只有 1 次真实 VLM 调用**（一个像素级阴影重绘产生的"无 DOM 信号"横条），类型准确率 100%
2. **hint 臂的两个错误正好是 tiered 按构造修掉的**：容器膨胀盖过新增元素（根因归因解决）、border 颜色变化被归成 style（模板直接点名属性）
3. **纯 VLM 全图的模式很稳定**：描述能力其实很强（检出时 95.7% 准确），但"找"的能力不行——30 对漏了 7 对，且三轮实验都是同一类失败（细微颜色/位移）

Token 节省 **98.9%**，比当初预估的 60–80% 还要高。

### 跨模型复现：换个厂商再跑一遍

单模型的结论可能是巧合，所以用第二个厂商的模型（qwen3.8-max）把四臂协议原样重跑了一遍：

| 模型 | tiered: 召回/FP/类型 | tiered tokens | hint 类型 | 无 hint 类型 | raw 召回 |
|------|---------------------|---------------|----------|-------------|---------|
| kimi-k3 | 100% / 0% / **100%** | 11+4 | 93.3% | 56.7% | 76.7% |
| qwen3.8-max | 100% / 0% / **100%** | 9+17 | 90.0% | 90.0% | 83.3% |

三个跨厂商都成立的发现：

1. **tiered 臂在两个模型上完全一致**（100%/0%/100%，升级率都是 1.3%）——这其实是按构造的必然：确定性层的路由和描述与模型无关，逐字节相同，只有那 1 次升级调用的结果依赖模型
2. **纯 VLM 的召回天花板是跨厂商的**（76.7% / 83.3%）：视觉模型"找不到"细微变化这个毛病，不挑厂商
3. **新发现：裁剪消融的严重程度是模型相关的**。Kimi 没有提示时崩到 56.7%，qwen 却能稳在 90%——"裁剪丢参照系"对不同模型的伤害差异很大。但在两个模型上 hint 臂都没赢过 tiered，而且确定性层顺便解决了输出不稳定问题（qwen 的 hint 臂平均输出 2321 tokens/对，是 Kimi 的 6 倍；tiered 恒定 ~10）

多模型聚合一键出表：`npm run compare:models`。

### 盲评裁判：模板文案 vs VLM 文案，谁更好读？

类型准确率已经分出胜负了，但还有一个问题：**模板生成的文案，人读起来和 VLM 写的比呢？**

让 qwen3.8-max 当裁判（和写 VLM 文案的 Kimi 不同厂商，避免自评偏好的干扰），30 对样本、标签随机、盲评打分：

| 维度（1–5 分） | tiered（模板） | VLM |
|---------------|---------------|-----|
| accuracy | 3.90 | **4.27** |
| specificity | **3.90** | 3.73 |
| readability | **4.60** | 4.50 |
| **胜场** | **14** | **14**（2 平） |

平分秋色，但赢法完全不同：

- **模板赢在精确**：`font weight changed from semibold (600) to normal (400)`、`resized by +84×+20px (+35%)`——VLM 只会说"文字变细了一点"
- **VLM 赢在会说话**：它说"蓝色的 Confirm 按钮被删了"，模板只会说"element #btn-confirm was removed"——DOM id 是开发者语言。这也指明了模板的改进方向：把元素的可见文本带进 diff
- **裁判自己也会犯错**：有一对样本，ground truth 是新增元素，VLM 描述成了"容器变窄 76px"（事实错误），裁判却给了 5/4/5 的高分——所以精确匹配的类型评分（tiered 100% vs 93.3%）依然是更硬的标尺

综合结论：**描述质量打平，成本差 98.9%**。

### CI 回归门禁

顺手把回放做成了 CI 门禁：`npm run replay:assert` 会在升级率超过 5% 时 fail——以后谁改了检测/描述逻辑导致本来能确定性描述的区域被迫送 VLM，CI 直接拦住。

## v0.2 更新：把上一版自己列的坑填了

上一版的"局限性"章节列了五个坑，这次迭代把其中四个正面解决了：

**1. 修复算法自相矛盾：canvas 路径从死代码变成活路径。** 旧规则"DOM 没变 → 一律无变化"把升级路径对 canvas 重绘这类核心用例永久关闭了。新规则按噪声阈值分流：低于帧面积 0.2% 的像素差仍被抑制，超过阈值的"纯像素变化"升级给 VLM，且 VLM 全部回答"无实质变化"时整对样本端到端翻回无变化——误报率变成诚实的端到端度量。数据集新增 media fixture（canvas/SVG/img）和 4 个纯像素突变（canvas 重绘 ×2、SVG 填充、图片替换）专门压测这条路径。

**2. 无变化样本 6 → 42 对。** 0% 误报率的 95% CI 上界从约 46% 收紧到约 8%。所有指标现在有 Clopper-Pearson 精确置信区间，臂间差异用 McNemar 精确检验（`npm run stats:report`）：tiered vs raw 召回差异显著（p=0.016），tiered vs hint 类型准确率差异**不**显著（p=0.5，30 对样本下 6.7pp 在噪声范围内）——这是旧版点估计说不清楚的。

**3. 循环论证有了真实数据回答。** 写了 `validate-real-repo.ts`：给定 git 仓库和两个 commit，worktree 检出、Playwright 渲染、离线跑完整管线，用 git-diff 做 ground truth。在两个真实开源仓库（mdn 的两个教学站点）上跑了 6 个场景：**0 误报、0 漏检**。图标图片文件被替换（同路径、零 DOM 信号）→ 100% 升级，正是设计行为；CSS 重构 → 12 个区域里 10 个确定性；`lang` 属性、字体 URL 协议、JS 交互修复这类"源码变了但视觉没变"的场景被正确判为无变化（脚本把这类"视觉静默"和真正的漏检分开统计）。过程中还修了个真实 bug：真实页面两个版本高度不同时，全页截图尺寸不匹配会直接崩——现在自动归一化到公共画布。

**4. 裁判做了人工校准。** 对盲评的 30 对全部人工标注描述正确性：27/30 对两侧描述都正确（和 14/14/2 的平局结论一致）；3 对事实错误恰好都是裁判判 VLM 赢的那几对——裁判的 vlm 偏好集中在错误描述上。裁判-人工一致率 66.7%/80%：聚合信号可用，逐对裁决不可信。另外 bootstrap CI 显示三个维度的分差区间都跨零——"模板与 VLM 质量无显著差异"这个结论本身变得可辩护了。

**5. 变成真正能用的工具。** `vlm-diff` CLI 可以 diff 任意两张截图（`vlm-diff diff before.png after.png --dom-before b.json --dom-after a.json`，无 DOM 时优雅降级为纯像素+VLM 模式，退出码 0/1/2 可直接进 CI）；MCP server（`diff_screenshots` + `snapshot_url` 两个工具）让编码智能体直接获得视觉回归能力。README 里宣传但实际是坏的 demo 脚本链（导入不存在的模块、数据形状不符）全部重写为真实代码。还有一串实修：缓存键加入模型身份（换模型不再静默返回旧模型结果）、价格表合并（未知模型警告而非静默 $0）、评测逐对错误隔离 + 断点续跑、重试最坏等待从 3.4 小时降到约 1 分钟。

数据集 145 → 185 对，单测 117 → 155 个。回放升级率从 0.7% 升到 3.2%——这个"退步"正是目的：新增的纯像素对按构造必须升级，CI 门槛继续守着 5%。

## 局限性（坦率版，v0.2 更新）

1. **循环论证部分退休，没有完全退休**：纯像素类别 + 6 个真实仓库场景给了边界数据，但第三方组件（广告、聊天窗、地图）这类"像素因你代码之外的原因变化"的场景仍未验证。
2. **fixture 仍以合成为主**：7 个手写页面，没有响应式断点、虚拟滚动、真实广告/时间戳；真实仓库覆盖 2 仓库 6 场景，是开始不是基准。
3. **无变化样本 42 对**（上界约 8%）——有意义了，但仍是合成的；真实动态页面上的无变化行为未测。
4. **裁判校准后依然只适合做聚合信号**：逐对正确性一致率 66.7–80%，逐对裁决别信。
5. **亚敏感度变化天生不可见**：低于 pixelmatch 灵敏度（~0.15 YIQ）的变化，比如 2px SVG 描边换色（仅占帧 0.04%），任何噪声阈值下都测不到。
6. ~~**v0.2 的 51 对子集在线重跑待做**~~ **已跑完（2026-09-02，qwen3.8-max，$1.36）**：tiered 召回 100% [CI 89.7–100%]、FP 0%（17 对 no-change，上界收紧到 19.5%）、端到端类型准确率 97.1%——唯一"失分"是图片替换对被 VLM 判成 color-change（ground truth 是 other，但描述"图标从蓝变红、图形不变"事实上完全正确，属于标签粒度问题）。4 个纯像素媒体对全部正确分类，升级路径被真实压测；升级率 18.7%（子集刻意含像素对）的情况下 token 节省仍是 90.2%。McNemar：tiered vs raw 召回 5/0 不显著（p=0.063，样本量上去了但同向）。单模型说明：这个 DashScope 账号只开通了 qwen3.8-max（kimi/GLM 运行时被拒，qwen3.7-max 是纯文本），跨厂商证据仍沿用 v0.1 的 kimi+qwen 双报告。

## 总结

这次迭代最大的收获是一个思路上的升级：

> **第一阶段我们用 DOM 回答"哪里变了"——这省掉了 VLM 的定位工作。**
> **第二阶段我们用 DOM 回答"变成了什么"——这几乎省掉了整个 VLM。**

不要盲目追求 AI 替代一切。先问一句：**这个领域里有没有结构化的 ground truth，能直接把问题变成确定性的？** 有的话，AI 只需要处理剩下那 0.7%。

前端测试领域还有很多这样的机会：
- **E2E 测试**：LLM 生成 Playwright 脚本 + 静态分析验证选择器稳定性
- **性能监控**：VLM 识别布局抖动 + Lighthouse 量化指标
- **无障碍审计**：VLM 检查视觉问题 + axe-core 校验 ARIA

期待看到更多「混合智能」的探索 🚀
