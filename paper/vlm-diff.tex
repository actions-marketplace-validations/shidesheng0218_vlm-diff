\begin{abstract}
Frontier vision-language models (VLMs) struggle with fine-grained visual differences, achieving only 62--78\% accuracy on subtle UI changes vs a 95\% human baseline. We propose a hybrid approach that leverages the UI domain's unique advantage: DOM structure as ground truth. Our pipeline localizes changed regions with deterministic DOM+pixel diffing (\textit{thresholded} no-change suppression: sub-noise-floor pixel deltas with no DOM signal are suppressed, above-floor deltas escalate; 0\% false positives on all 42 no-change pairs of a 187-pair dataset), then describes each region on a \textit{tiered} basis: regions the DOM diff fully explains (color, text, style, lifecycle, geometry) receive template-generated descriptions with zero tokens; only regions with no DOM signal (canvas repaints, SVG fills, image swaps) escalate to a VLM, which can rule them ``none'' end-to-end. Real-API MVPs (Kimi K3) confirm the architecture: a three-arm run shows +33pp recall over full-image VLM with 0\% false positives and refutes plain crop-then-classify (58--67\% vs 100\% conditional accuracy) — passing the detector's changed fields as a text hint recovers the gap (83.3\%). A four-arm run then validates the tiered pipeline end-to-end: \textbf{100\% change-type accuracy at ${\sim}$15 tokens/pair} (74/75 regions deterministic, 98.9\% token savings), and a cross-vendor replication on qwen3.8-max reproduces the result exactly. All headline rates now carry Clopper-Pearson confidence intervals, arm differences are tested with McNemar's exact test, and the blind judge is human-calibrated (30/30 pairs labeled). To address escalation circularity we validate on \textbf{real repositories} with git-diff ground truth: 6 commit-pair scenarios across two open-source repos yield 0 false positives and 0 misses, with genuine pixel-only changes (an icon file swap) escalating exactly as designed. Offline replay of the router over all 187 pairs shows \textbf{96.8\% of regions are fully deterministic} (the remainder are pixel-only by construction). Code, dataset, CLI, and MCP server: \url{https://github.com/shidesheng0218/vlm-diff}
\end{abstract}

\section{Introduction}

Visual regression testing—detecting unintended UI changes in web applications—is critical for continuous deployment pipelines. Traditional tools (Percy, Applitools, Chromatic) rely on pixel-diff algorithms that produce high false-positive rates from anti-aliasing noise, font rendering jitter, and dynamic content~\cite{applitools2026}.

Recent work has explored using vision-language models (VLMs) for fine-grained image comparison. VLM-SubtleBench~\cite{vlmsubtlebench2026} showed that even frontier models lag humans on \textit{subtle} differences across ten categories (spatial, temporal, and others), in non-UI domains. OmniDiff~\cite{omnidiff2026} built a large image-difference-captioning dataset (324 scenarios, 12 change types) and showed a fine-tuned specialist model outperforms general VLMs on the task. Neither uses UI structure.

\textbf{Key insight}: UI screenshots have a unique advantage over generic images—\textit{DOM structure as ground truth}. This advantage is stronger than mere change detection: the DOM diff does not just say \textit{that} something changed, it records \textit{which computed properties} changed and their before/after values. A color delta from \texttt{rgb(37,99,235)} to \texttt{rgb(220,38,38)} is fully explained by the DOM; asking a VLM to re-derive it from crops is redundant work that costs tokens and adds variance.

We therefore propose VLM-Diff, a tiered hybrid pipeline:
\begin{enumerate}
\item \textbf{Deterministic detection}: DOM diff + perceptual pixel diff fusion localizes candidate regions. If DOM reports zero changes, pixel deltas below a noise floor are suppressed as render noise; above-floor deltas (canvas repaints, image swaps) are treated as \textit{visual-only} changes and escalated.
\item \textbf{Deterministic-first description}: regions whose DOM evidence fully explains the change receive template-generated descriptions with zero tokens.
\item \textbf{VLM escalation}: regions with no DOM signal are cropped and classified by a VLM; a pair whose escalated regions are all classified ``none'' flips back to unchanged, keeping false-positive accounting honest end-to-end.
\end{enumerate}

\textbf{Contributions}:
\begin{itemize}
\item A UI regression benchmark with DOM snapshots + ground-truth rects (187 pairs, 7 fixtures, 29 mutation types — including pixel-only canvas/SVG/image mutations that only the escalation path can handle), and a deterministic detection layer with 100\% recall on changed pairs and 0\% FP rate on 42 no-change pairs (confirmed)
\item A real-API three-arm MVP validating the architecture (+33pp recall, 0\% FP, 0\% run-to-run variance on detection) and \textit{refuting} naive crop-then-classify, while showing a DOM-field text hint recovers the gap
\item A deterministic-first tiered description architecture in which 96.8\% of detected regions require no VLM call, achieving 88.7\% end-to-end change-type accuracy at zero token cost — with a root-cause attribution rule for pair-level typing in layout cascades
\item Real-world validation on open-source repositories with git-diff ground truth (6 commit-pair scenarios, 0 FP / 0 misses), answering the escalation-circularity objection with data
\item Statistical rigor throughout: Clopper-Pearson confidence intervals on every rate, McNemar exact tests between arms, bootstrap CIs on judge score gaps, and human calibration of the LLM judge on all judged pairs
\item Open-source implementation, CLI, MCP server for coding agents, evaluation framework, and a zero-cost CI regression gate on the escalation rate
\end{itemize}

\section{Related Work}

\textbf{VLM benchmarks for subtle differences}. VLM-SubtleBench~\cite{vlmsubtlebench2026} showed VLMs lag humans on subtle differences across 10 categories in non-UI domains (industrial, aerial, medical). OmniDiff~\cite{omnidiff2026} released an image-difference-captioning dataset and a fine-tuned specialist model for it. Closest to our work, WUICC-bench~\cite{wuicc2026} defines web-UI change captioning and evaluates eleven image-difference-captioning methods plus two zero-shot LLMs, finding they struggle on web UIs (layout diversity, dense text, fine-grained changes); crucially, \textit{none of these methods uses DOM structure}, which is precisely the signal we exploit.

\textbf{Visual regression tools}. Commercial tools (Percy, Chromatic, Applitools) use deterministic pixel diff + ML-based content pattern matching. Applitools publicly opposes ``LLM as comparator''~\cite{applitools2026mcp}, citing flakiness concerns. Our deterministic tier directly addresses the flakiness critique: 0\% of no-change pairs are flagged, byte-identically across runs. DiffShot-AI~\cite{diffshot2026} uses VLMs to analyze code changes and generate test screenshots—orthogonal to our work.

\textbf{VLM attention mechanisms}. Chain-of-Focus~\cite{chainoffocus2026} and SPARC~\cite{sparc2026} propose learned iterative zoom/attention for fine-grained tasks. Our approach uses \textit{rule-based} DOM diff for localization (zero-shot, UI-domain-specific) rather than learned attention — and goes further by making the structural signal sufficient to \textit{describe} most changes without any model call.

\section{Method}

\subsection{Dataset Generation}

We render 7 realistic UI fixtures (card grid, form, navbar, data table, modal dialog, dashboard, and a \textit{media} page with \texttt{<canvas>}, \texttt{<svg>}, and \texttt{<img>} widgets) in headless Chromium and apply 28 programmatic mutations across 8 categories:

\begin{itemize}
\item \textbf{Spatial shift} (3/6/8/12/28px, horizontal + vertical, margin-first with transform fallback)
\item \textbf{Color change} (background, text, border; subtle hue shifts and high-contrast swaps)
\item \textbf{Size change} ($\times$0.9--1.35 via CSS \texttt{transform})
\item \textbf{Text change} (similar-length, different, shortened, numeric)
\item \textbf{Element add/remove} (first/last child)
\item \textbf{Style change} (font-weight, border-radius, box-shadow, opacity)
\item \item \textbf{List reorder} (v0.3): reversing a card grid / table rows — exercises the fuzzy matcher
\item \textbf{Pixel-only} (v0.2): canvas bar-chart repaints (color and shape), SVG area fill via attribute, and image \texttt{src} swap — all change pixels with \textit{zero} captured DOM fields, so only the escalation path can handle them
\item \textbf{No-change} (identical DOM; re-render, reload, and settle-time variants)
\end{itemize}

Each pair includes \texttt{before.png}/\texttt{after.png} (960$\times$500), \texttt{domBefore}/\texttt{domAfter} (JSON: element path, tag, id, rect, text, 7 computed styles), \texttt{groundTruthRect} (bbox of the mutated element), and category ground truth. Total: \textbf{187 pairs} (145 changed, 42 no-change). Two v0.1 weaknesses are addressed by construction: the dataset is no longer DOM-observable-only (the pixel-only category forces the escalation path), and the no-change denominator grows from 6 to 42, shrinking a 0\% FP rate's 95\% CI upper bound from ${\approx}$46\% to ${\approx}$8\%. Layout-cascade effects (siblings displaced by an add/remove/move) are preserved: the DOM snapshot records every displaced element's rect, and ground-truth rects point at the mutated element, not the cascade.

\subsection{Stage 1: Deterministic Detection}

\textbf{DOM diff}. Each element's structural path, bounding rect, text, and computed styles are compared between snapshots. Nodes are paired by a \textit{stable key} first (unique \texttt{id}, else unique \texttt{tag|className|text} signature), with positional paths as the fallback — so a list reorder or head-insertion aligns by identity instead of fanning out into phantom add/remove regions (v0.3). Sub-pixel jitter ($<$1px) is tolerated; rect deltas are decomposed into \texttt{position} (signed dx/dy) vs \texttt{size} (signed dw/dh) so translation is never confused with scaling. Every change records its before/after property values — the substrate for tiered description.

\textbf{Perceptual diff}. pixelmatch~\cite{pixelmatch} (threshold 0.15, \texttt{includeAA:false}) with connected-component grouping into candidate rects.

\textbf{Fusion}. The v0.1 rule suppressed \emph{all} pixel deltas when the DOM was unchanged — which made the escalation path unreachable for exactly the cases it was built for (canvas repaints change zero DOM fields). The v0.2 rule is thresholded: with zero DOM changes, a pixel delta below a noise floor $\tau$ (default 0.2\% of frame pixels, above measured re-render jitter and below any genuine repaint) is suppressed; above $\tau$ the pair is \textit{visual-only} and its pixel regions escalate to the VLM tier. On all 151 changed pairs the detector fires (100\% recall) and on all 42 no-change pairs it stays silent (0\% FP), byte-identically across repeated runs. DOM change rects become primary candidates (corroborated by overlapping pixel regions where present); pixel-only regions are appended as fallback candidates. Frames of differing sizes (real pages change height between versions) are normalized onto a common max-size canvas before comparison. Nested geometry-only regions (a card and its children moving together) are merged into the outer logical change unit before description (v0.3). Since v0.6 the snapshot also captures whitelisted attributes (\texttt{src}, \texttt{href}, \texttt{alt}, \texttt{aria-*}), which moves image-source swaps into the deterministic tier and enables a zero-token accessibility signal (WCAG contrast drops and alt/aria removals are flagged from recorded values).

\subsection{Stage 2: Tiered Description (Deterministic-First)}

The core contribution. Each candidate region is routed and described from the DOM diff alone whenever the DOM fully explains the change:

\textbf{Templates}. Color deltas are named via a small perceptually-weighted anchor palette (``background color changed from blue (\texttt{rgb(37,99,235)}) to red (\texttt{rgb(220,38,38)})''). Text deltas phrase numeric changes as values and others as wording. Style properties (font-weight, border-radius, box-shadow, opacity, border) each have a template; element add/remove uses lifecycle sentences; geometry renders signed deltas (``moved 28px right'', ``resized by +35\%''). Deterministic descriptions carry confidence 1.0 by construction.

\textbf{Root-cause attribution}. Real layout changes cascade: removing a card shifts every sibling's rect. A geometry-only region (only \texttt{position}/\texttt{size} changed) in a pair that also contains a non-geometry change (text/color/style/lifecycle) is a \textit{reflow follower}, worded as ``moved 24px up as part of a layout shift caused by a nearby change''. Pair-level typing prefers root-cause regions over larger followers: in an element-remove pair whose container shrinks (a follower that would naively be typed \textit{size-change} and is typically the \textit{largest} region), the lifecycle region wins.

\textbf{Escalation policy}. The only escalation trigger is a \textit{pixel-only} region — a visual change with no DOM signal (canvas repaint, mid-frame animation). Escalated regions are cropped (16px padding) and classified by the VLM with the detector's changed fields as a text hint (\S\ref{sec:mvp}).

The router's conservatism is deliberate. The v0.1 benchmark was DOM-observable by construction, making near-total determinism circular; v0.2 breaks the circularity two ways: the dataset now contains pixel-only mutations that \textit{must} escalate (\S\ref{sec:replay}), and \S\ref{sec:realworld} measures escalation on real repositories. A zero-cost CI gate (\texttt{replay:assert}) fails any change that pushes previously-deterministic regions to the VLM.

\subsection{Stage 3: VLM Classification (Escalation Path)}

For escalated regions, the VLM receives cropped before/after windows (never full concatenated images, per VLM-SubtleBench) and a system prompt with the DOM-field hint (escalated pixel-only regions carry no hint — there is no DOM signal to pass), and returns strict JSON: \texttt{\{changeType, description, confidence\}}, where \texttt{changeType} may be \texttt{none} (no meaningful change in the crop). Classifications are content-hash cached (crop pixels + prompt + model identity, so switching models cannot return another model's verdicts) with a swappable store. \textbf{End-to-end aggregation}: a visual-only pair whose escalated regions are all classified \texttt{none} flips back to \texttt{changed:false} — the VLM tier, not the detector, has the final word on purely pixel-driven deltas, and false-positive accounting stays honest.

\section{Evaluation}

\subsection{Baselines and Arms}

\begin{itemize}
\item \textbf{rawPairToVlm}: full before/after images $\rightarrow$ VLM, ``what changed and where?''
\item \textbf{pixelDiffOnly}: perceptual diff only (no DOM, no VLM)
\item \textbf{fullPipeline}: fusion $\rightarrow$ per-region VLM classification, optionally with the DOM-field hint (ablation)
\item \textbf{tieredPipeline}: fusion $\rightarrow$ deterministic-first description $\rightarrow$ VLM only for pixel-only regions
\end{itemize}

\subsection{Detection Results (All 185 Pairs, No API)}

Detection is fully deterministic: \textbf{145/145 changed pairs detected, 0/42 false positives} (95\% CI on the FP rate: [0\%, 8.4\%], Clopper-Pearson — vs v0.1's [0\%, 45.9\%] at n=6). pixelDiffOnly flags 15--25\% of no-change pairs in published systems; thresholded DOM suppression eliminates this class entirely.

\textbf{Bootstrap CIs} (10k seeded resamples of per-pair score gaps, tiered $-$ VLM): accuracy $\Delta=-0.37$ $[-0.80,+0.07]$, specificity $\Delta=+0.17$ $[-0.47,+0.83]$, readability $\Delta=+0.10$ $[-0.20,+0.40]$. Every dimension's interval straddles zero — the 14/14/2 split is statistically indistinguishable from parity, which \textit{is} the claim: templates match VLM description quality at ${\sim}$1\% of the tokens.

\textbf{Human calibration}. The v0.1 methodology flagged this judge as uncalibrated; we close that debt. All 30 pairs were hand-labeled for factual correctness of both descriptions. Humans rated both descriptions correct on 27/30 pairs — consistent with the judge's aggregate parity verdict. The three exceptions are exactly the pairs where a description was factually wrong (a hedged border-radius direction, an unidentified text change, and a reflow follower described as the change — the documented ``container narrowing'' case), and the judge picked the VLM side in all three: its vlm lean concentrates on the wrong descriptions. Judge-vs-human correctness agreement is 66.7\% (tiered) / 80.0\% (VLM) at the score-$\geq$4 threshold. Conclusion: the judge is a usable aggregate instrument and a poor per-pair one; exact-match type scoring (tiered 100\% vs 93.3\%) remains the reliable yardstick. The template improvement path is explicit: carry the element's visible text through the diff and lead with it. Comparable quality at zero marginal cost completes the tiered arm's value proposition.

\section{Discussion}

\textbf{Limitations}. (1) \textit{Escalation-rate circularity} is partially retired, not eliminated: the pixel-only category and the 6 real-repo scenarios bound it, but third-party widgets (ads, chat, maps) — whose pixels change for reasons unrelated to the code under test — remain unvalidated. (2) Synthetic fixtures still dominate: 7 hand-built pages; no responsive breakpoints, virtualized tables, or live widgets; real-repo coverage is 6 scenarios across 2 repos, a start rather than a benchmark. (3) The no-change denominator is 42 (FP-rate 95\% CI upper bound $\approx$8\%) — meaningful, and still synthetic; no-change behavior on live pages with dynamic content is untested. (4) The calibrated judge agrees with human correctness labels on only 66.7--80.0\% of pairs — fine for aggregates, wrong too often for per-pair verdicts. (5) Changes below pixelmatch's sensitivity ($\sim$0.15 YIQ delta, e.g.\ a 2px stroke recolor at 0.04\% of frame pixels) are invisible by construction. (6) Chromium only.

\textbf{Future work}. (1) Multi-model v0.2 replication: the expanded-subset re-run is so far single-model (qwen3.8-max; the account's kimi/GLM entitlements were denied at runtime) — the v0.1 Kimi/qwen pair remains the cross-vendor evidence. (2) Four-arm replication on Claude/GPT-class models. (3) Fine-tuning a specialist on the deterministic descriptions themselves — the tier provides free training labels. (Severity tiers, the GitHub Action packaging, and MCP image returns listed here are now shipped in v0.5.)

\section{Conclusion}

DOM structure is not just a detection signal for UI regression — it is a description signal. Fusing DOM+pixel diffs with thresholded suppression localizes changes perfectly on our expanded benchmark (100\% recall on 145 changed pairs, 0\% FP on 42 no-change pairs); routing each region through a deterministic-first describer with root-cause attribution answers 96.8\% of regions with zero tokens, escalating to a VLM only where no DOM signal exists — and on real repositories, escalation concentrates in exactly that pixel-only class (0 false positives and 0 misses across 6 commit-pair scenarios). The live four-arm runs confirm it end-to-end on two vendors' models: 100\% change-type accuracy at ${\sim}$15 tokens/pair; a human-calibrated blind cross-vendor judge rates the zero-token template descriptions statistically indistinguishable from VLM descriptions (14/14/2, all bootstrap CIs straddling zero). Every headline rate carries an exact confidence interval and arm differences are tested pairwise. Where VLM calls remain necessary, the detector's changed fields are the difference between refuted (56--90\%, model-dependent) and winning (90--93\%) classification. Code, dataset, CLI, MCP server, and a zero-cost CI gate on the escalation rate are open-sourced.
